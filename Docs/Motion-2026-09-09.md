# Design and motion update — 9 September 2026

## Interface changes

The overview has a more compact header with an explicit Scan now action, coordinated section entrances, tactile metric cards, and native numeric transitions. The sidebar's primary selection and process-filter selection use moving highlight surfaces rather than animating the entire process list. Hover and press effects stay local to their controls; live process identities and destructive-action behavior are unchanged.

Thermal telemetry now includes bounded traces of actual CPU and GPU sensor readings. The overview keeps up to 60 samples within three minutes, rejects duplicate, stale, and future timestamps, and breaks each component's trace at missing readings or long gaps. Invalid readings never become zero-degree points. The visible range caption explains the trace's scale. The panel distributes its three tiles across the available width and adapts when space is constrained. Views without supplied history display readings without promising a trace they cannot populate.

The scope has finer range markings, smaller target glows, hover targeting feedback, and short transitions when a family's radial position changes. Continuous sweep motion remains a Core Animation transform, not a per-frame SwiftUI timer. Layer-local time is preserved when pausing, and the local clock is established before creating the first animation. Decorative motion pauses for offscreen, inactive, hidden, low-power, and Reduce Motion conditions. A power-saving/reduced-motion explanation is included in the scope.

## Engineering

`RadarMotion.swift` centralizes finite animation timing and accessibility behavior. `RadarPresentationModels.swift` contains independently testable history, geometry, and motion-policy logic. Sensor-history updates only publish when a new eligible sample is accepted. `ConsoleThermalDashboard` isolates thermal observation from the surrounding overview.

The console now keeps one stable navigation shell with one search modifier, instead of replacing the shell when entering a section without family controls. Typing a process search from Engine routes to the browser; scene state is restored once rather than being reapplied during navigation.

Existing detection, baseline, sensor-reader, database, approval, and process-stop implementation files were not changed by this pass. The source, tests, working-tree inventory, and previous application bundle were backed up under `.build/motion-before/` before editing.

## Limits of verification

The Mac was already configured for Low Power Mode on both battery and AC power. Those settings were not changed. The continuous sweep was observed paused; a running-sweep/resume cycle was not verified live in this configuration. The motion gates and geometry were unit-tested, but this is not an FPS benchmark, an Instruments energy profile, or an exhaustive accessibility audit.

Some combined shell requests were blocked by tool screening; the successful individual build/test results above are the evidence used here. Additional CUA Quiet-filter clicks and a later lower-radar scroll were also blocked, so those particular live checks were not completed. A successful build is not represented as proof that every animation path was observed on screen. No real process-stop action was exercised in this pass.
