# Cleanup feature status

Started 2026-09-15. The core is implemented and tested; the user-facing feature is not built, so nothing in the app can clean files yet.

## Implemented core

`Sources/GhostProcessSniperCore/Cleanup/`:

- `CleanupScanner`: bounded local file scans, age-based cache/log/installer candidates, large files, and SHA-256 duplicate comparisons.
- `CleanupApplications`: installed-app inventory and exact bundle-ID data discovery for reset/uninstall review.
- `CleanupPlan`: explicit selection, expiry metadata, retained duplicate proofs, and overlapping-selection rejection.
- `CleanupTransaction`: per-item validation, Trash moves, recovery journal, partial outcomes, and conflict-aware restoration. An uncertain move stops the rest of the batch.
- `CleanupFileSystem`: path boundaries, file identities, content fingerprints, and changed-file rejection.

Scans skip linked, cloud-managed, package and unsupported entries and report partial coverage. Duplicate comparison uses a bounded read budget. Byte totals describe logical size, not guaranteed disk space recovery.

App-data review deliberately excludes shared containers, keychains, cloud data, system helpers and name-only matches. It is not a complete factory reset. Running apps must be quit by the user before their associated files can be changed.

## Tests

`Tests/GhostProcessSniperCoreTests/CleanupTests.swift` moves only synthetic files inside `~/Library/Caches/GhostProcessSniperTests/cleanup/`, because the scanner refuses system temporary and iCloud-managed folders. Native macOS Trash integration has not been exercised end to end, and no real app has been reset or uninstalled.

## Not built yet

A cleanup session and console view, navigation into the console, and any packaging or live interaction. Until they exist, the Cleanup folder is library code with no caller in the app.
