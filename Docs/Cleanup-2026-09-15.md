# Cleanup feature implementation status

Date: 2026-09-15
Status: Core implemented; user-facing feature unfinished.

## Implemented core

- `CleanupScanner`: bounded local file scans, age-based cache/log/installer candidates, large files, and SHA-256 duplicate comparisons.
- `CleanupApplications`: installed-app inventory and exact bundle-ID data discovery for reset/uninstall review.
- `CleanupPlan`: explicit selection, expiry metadata, retained duplicate proofs, and overlapping-selection rejection.
- `CleanupTransaction`: per-item validation, Trash moves, recovery journal, partial outcomes, and conflict-aware restoration.
- `CleanupFileSystem`: path boundaries, file identities, content fingerprints, and changed-file rejection.

Scans skip linked, cloud-managed, package and unsupported entries and report partial coverage. Duplicate comparison uses a bounded read budget. Byte totals describe logical size, not guaranteed disk space recovery.

App-data review deliberately excludes shared containers, keychains, cloud data, system helpers and name-only matches. It is not a complete factory reset. Running apps must be quit by the user before their associated files can be changed.

No personal files were cleaned and no real app was reset or uninstalled during implementation. Tests move only synthetic files inside `.build/cleanup-tests`; native macOS Trash integration has not been exercised end to end.
